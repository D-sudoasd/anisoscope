# Security policy

## Supported versions

Until AnisoScope has tagged releases, security fixes are prepared against the
current default branch. After the first release, the latest release line will be
the supported version unless a release note states otherwise.

## Reporting a vulnerability

Do not include exploitable details, confidential data, or unpublished research
inputs in a public issue. Use GitHub's private vulnerability reporting or open a
private security advisory for this repository. Include the affected version or
commit, operating system, reproduction steps, impact, and any proposed
mitigation.

If private reporting is unavailable, contact the repository owner through the
public profile and ask for a private reporting channel without disclosing the
vulnerability details. This volunteer project does not promise a fixed response
time; maintainers will provide a status update when the report has been triaged.

Scientific disagreements, incorrect results without a security impact, and
ordinary crashes should be reported through the public issue tracker.
